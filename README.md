# ThermoStep 🌡️🦶

แอปคู่กับ **แผ่นรองในรองเท้าอัจฉริยะ** ที่ตรวจจับ "จุดร้อน" บนฝ่าเท้าของผู้ป่วยเบาหวาน
เพื่อเตือนก่อนที่จะเกิดแผล — ต้นแบบ (prototype) สำหรับการประกวดนวัตกรรมทางการแพทย์

> **แนวคิดทางการแพทย์**
> แผ่นรองมีเซ็นเซอร์อุณหภูมิ **6 จุดต่อเท้า 1 ข้าง (รวม 12 จุด)** ระบบเปรียบเทียบจุดเดียวกัน
> ของเท้าซ้ายกับเท้าขวา ถ้าจุดใดร้อนกว่าคู่ของมัน **≥ 2.2°C ติดต่อกัน 3 วันขึ้นไป**
> นั่นคือสัญญาณเตือนว่ากำลังจะเกิดแผล ซึ่งเกิดขึ้นก่อนที่จะเห็นแผลด้วยตาหลายวัน
> ผู้ป่วยเบาหวานมักไม่รู้สึกเจ็บเพราะปลายประสาทเสื่อม — การวัดนี้จึงทำหน้าที่แทน "ความรู้สึก" ที่หายไป

## เริ่มใช้งาน

```bash
npm install
npm run dev      # เปิด http://localhost:5173
npm run build    # build ไปที่ dist/
npm run preview  # ดู production build
```

ออกแบบสำหรับหน้าจอมือถือ **390 × 844** (บนจอคอมจะแสดงเป็นกรอบโทรศัพท์ให้อัตโนมัติ — เหมาะกับการนำเสนอบนโปรเจกเตอร์)

**Stack:** React 18 (SPA, ไม่มี router/backend) · Vite · Tailwind CSS · ฟอนต์ Kanit · กราฟเป็น SVG เขียนเอง (ไม่มี chart library)

### เกณฑ์สี (ผลต่างซ้าย–ขวา)

| สี | ช่วง | ความหมาย |
|----|------|----------|
| 🟢 เขียว | < 1.5°C | ปกติ |
| 🟡 เหลือง | 1.5 – 2.2°C | เฝ้าระวัง |
| 🔴 แดง | > 2.2°C | ร้อนผิดปกติ — เสี่ยงเกิดแผล |

สีจะปรากฏบน **เท้าข้างที่ร้อนกว่า** เท่านั้น เพื่อให้อ่านเรื่องราวได้ทันทีว่าเท้าข้างไหนมีปัญหา
และทุกจุดมีทั้งไอคอน + ข้อความกำกับเสมอ ไม่ได้ใช้สีสื่อความหมายเพียงอย่างเดียว

## เรื่องราวในชุดข้อมูลจำลอง (14 วัน)

| ช่วง | เกิดอะไรขึ้น |
|------|--------------|
| วันที่ 1–7 | เท้าสองข้างต่างกันไม่เกิน 0.5°C ทุกจุดเขียว · เดิน 7,000–9,000 ก้าว/วัน |
| วันที่ 8–9 | โคนนิ้วโป้งขวาเริ่มร้อนขึ้น (0.8°C → 1.2°C) จากแรงกดซ้ำ ๆ ขณะเดิน |
| วันที่ 10–11 | เข้าโซนเฝ้าระวัง จุดเปลี่ยนเป็นสีเหลือง (1.6°C → 2.0°C) |
| วันที่ 12–14 | เกินเกณฑ์ 2.2°C ติดต่อกัน (2.3 → 2.6 → **2.8°C**) · ครบ 3 วัน → **ระบบแจ้งเตือนอัตโนมัติ** |

จำนวนก้าวลดลงในวันที่ 11–14 สะท้อนว่าผู้ใช้เริ่มเดินน้อยลงเมื่อเท้าเริ่มมีปัญหา
ข้อมูลสร้างจาก PRNG ที่กำหนด seed ไว้ — **เล่นกี่ครั้งก็ได้ตัวเลขเดิมทุกครั้ง** เหมาะกับการสาธิตสด

### การเปลี่ยนไปใช้เซ็นเซอร์จริง

**ไม่มีหน้าจอไหนเรียก `simulatedFeed.js` โดยตรง** — ทุกหน้าอ่านผ่าน `src/data/dataSource.js` เท่านั้น
การต่อฮาร์ดแวร์จริงจึงทำได้โดยเขียน object ใหม่ที่มี method ชุดเดียวกัน แล้วสลับที่จุดเริ่มแอป:

```js
// src/main.jsx
import { setDataSource } from './data/dataSource.js'
import { createBleDataSource } from './data/bleDataSource.js'

setDataSource(createBleDataSource({ deviceId })) // ไม่ต้องแก้หน้าจอใด ๆ
```

สัญญา (contract) ที่ต้องมีครบ:

| method | คืนค่า |
|--------|--------|
| `getConfig()` | เกณฑ์อุณหภูมิ, จำนวนวันที่ต้องเกินติดกัน, เป้าหมายก้าว |
| `getSensorPoints()` | รายการ 6 จุดวัด + พิกัดบนภาพ |
| `getTotalDays()` / `getLatestDay()` | จำนวนวันที่มีข้อมูล / วันล่าสุด |
| `getHistory()` / `getDay(day)` | ข้อมูลทั้งหมด / รายวัน |
| `getPointReading(day, id)` | ผลเทียบซ้าย–ขวาของจุดหนึ่ง |
| `getSeries(id, upToDay?)` | ชุดข้อมูลสำหรับกราฟแนวโน้ม |
| `getAlert(day)` | สถานะเตือนภัย (จุดไหน, เกินมากี่วันติด, เข้าเกณฑ์หรือยัง) |
| `subscribe(listener)` | รับข้อมูลสด, คืนฟังก์ชันสำหรับยกเลิก |

## แนวทางการออกแบบ

- **โทนการแพทย์:** พื้นขาว, น้ำเงินเข้ม `#0b4f9e` เป็นสีหลัก; เขียว/เหลือง/แดงสงวนไว้สำหรับสถานะเท่านั้น
- **ผู้ใช้สูงอายุ:** ตัวอักษรฐาน 17px, ปุ่มสูงอย่างน้อย 56px, จุดบนภาพเท้ามีพื้นที่แตะกว้างกว่าจุดที่เห็นประมาณ 2 เท่า
- **Transition นุ่มนวล 500–700ms** เวลาสีเปลี่ยน เพื่อให้เห็นชัดตอนอัดวิดีโอ (และปิดอัตโนมัติเมื่อผู้ใช้ตั้งค่า `prefers-reduced-motion`)
- กราฟใช้เส้นเดียว ไม่ต้องมี legend, ติดป้ายค่าเฉพาะจุดล่าสุด, เส้นตารางสีจาง, แตะ/ลากเพื่อดูค่าแต่ละวัน

## การ deploy ขึ้น GitHub Pages

`.github/workflows/deploy-pages.yml` จะ build แล้ว publish โฟลเดอร์ `dist/` ให้อัตโนมัติทุกครั้งที่ push

**ต้องตั้งค่าครั้งเดียวก่อน:** ไปที่ **Settings → Pages → Build and deployment → Source** แล้วเลือก **GitHub Actions**

ถ้าตั้งเป็น "Deploy from a branch" GitHub Pages จะเสิร์ฟไฟล์ใน repo ตามที่เป็น ซึ่งคือ `index.html` ของ Vite
ที่ยังไม่ได้ build (ชี้ไปที่ `/src/main.jsx` ซึ่งเป็น JSX ดิบที่เบราว์เซอร์รันไม่ได้) ผลคือ **หน้าขาว** —
HTML โหลดได้แต่แอปไม่ render

### เรื่อง base path

`base: './'` ใน `vite.config.js` ถูกต้องแล้วสำหรับ `user7468-available.github.io/thermo/`
asset จะถูกอ้างแบบ relative (`./assets/...`) ซึ่งแปลงเป็น `/thermo/assets/...` ให้เอง
**ไม่ควร** ฮาร์ดโค้ดเป็น `base: '/thermo/'` เพราะจะพังเวลา `npm run preview` และเวลาเอาไป host ที่อื่น

ทดสอบ build แบบ subfolder ก่อน deploy ได้ด้วย:

```bash
npm run build
mkdir -p /tmp/pages/thermo && cp -r dist/. /tmp/pages/thermo/
cd /tmp/pages && python3 -m http.server 8080   # เปิด http://localhost:8080/thermo/
```

## เคล็ดลับการอัดคลิปสาธิต

เปิดแอปบนมือถือ → กดปุ่มลอย **"สาธิต"** → กดลูกศร ▾ เพื่อย่อแผงควบคุม (จะได้เห็นข้อมูลเต็มจอ)
อยู่ที่หน้า **แผนที่เท้า** ช่วงวันที่ 1–11 ให้เห็นจุดเปลี่ยนจากเขียว → เหลือง → แดง
แล้วสลับไปหน้า **กราฟแนวโน้ม** ตอนวันที่ 12–14 เพื่อให้เห็นเส้นไต่ทะลุเส้นประแดง
พอถึงวันที่ 14 หน้าจอแจ้งเตือนสีแดงจะเด้งขึ้นเอง — จังหวะนี้ยาวประมาณ 28 วินาทีจากเริ่มเล่น
